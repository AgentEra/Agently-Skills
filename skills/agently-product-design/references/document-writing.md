# 文档撰写与读者走查

适用于方案、技术说明、操作指南、课程讲义、需求、评审和交接材料的起草、重构或审查。目标是让指定读者凭交付内容理解问题、作出判断或继续行动。下列流程是本 Skill 综合项目实践的方法；不是 ASD-STE100 原文，也不是经真人实验验证的教学模型。

## 1. 接手：确定读者任务与内容边界

先读项目写作规范、现稿、有效事实和已有审查记录。确认修改授权、目标语言、发布载体、唯一源稿、交付格式及需要保留的技术含义。资料中能查到的直接查；只对影响结论的未知前提提问。允许起草时继续写可确认部分，缺少的事实标为待补，不能为行文完整而编造。

新建时先形成读者目标与信息顺序；已有稿先通读标记，再改结构、段落和句子，最后全文复读。不以批量替词代替审读，也不因小段润色重做整份材料。共用身份、证据和修订约定见[共用规则](common-review.md)。

选择有实际知识差异的角色，不要求固定人数，也不必启动多个 Agent：

| 角色类型 | 合理已知 | 读完需要做到 | 常见知识越界 |
| --- | --- | --- | --- |
| 首次阅读者 | 当前正文、明确说明的基础知识 | 说清对象、问题、用途和适用边界 | 默认看过作者聊天、懂内部编号或旧方案 |
| 评审或决定者 | 职责范围内的目标和约束 | 比较依据、代价、未定条件并知道本次决定的效力 | 用“请确认附件”代替决定内容 |
| 执行或接手者 | 当前交付资料及明确可用的环境 | 找到前置输入，执行、检查结果，失败后继续 | 默认拥有前会话记忆、作者本机路径或未交付文件 |
| 跳读、返回查阅者 | 只从标题或搜索命中处进入 | 定位当前章节、理解指代、找回必要条件 | “同上”“照旧”只在另一页解释 |

读者是业务用户、开发者、授课者、学员还是模型，应分别说明。相同的人可承担多个角色，但知识与责任不自动互通。教师安排、作者备忘和评估答案放在适当的内部记录；正文保留读者完成任务所需的解释。

## 2. 写出连续阅读与行动路径

把读者故事写成“进入位置→遇到的问题→获得的概念/依据→判断或行动→可观察结果→下次找回”。每一段检查：读到此处才获得什么新知识，下一段需要什么，是否存在缺口。

按用途组织，不套固定八章，也不要求所有文档都有操作步骤：

| 主要用途 | 通常合适的顺序 | 关键检查 |
| --- | --- | --- |
| 方案与决策 | 待解决问题/建议→必要背景→选项与依据→取舍→决定与条件 | 建议可前置，但不能省略判断依据或把候选写成批准 |
| 概念与架构 | 具体问题或例子→职责与关系→机制→边界与适用条件 | 定义早于依赖它的推理；不从内部 API 名称堆起 |
| 操作指南 | 目标与适用范围→前置→顺序操作→检查结果→失败与恢复 | 操作环境、对象、输入输出、等待和停止条件可识别 |
| 讲义与实践材料 | 已知问题→必要概念→例子/实践→观察解释→可迁移条件 | 不靠口头补充；前一练习的输出能供下一练习使用 |
| 验证报告与交接 | 当前结论→范围/条件→关键证据→限制→剩余动作与责任 | 历史结果、模拟与当前实测分开，不用日志堆代替结论 |

对长文建立简短的依赖检查：概念首次解释在哪里；后面哪里使用它；缺少哪项输入就不能理解或执行。没有必要把这些作者记录全部放进读者正文。

### 阅读顺序与表达时序

按读者在当前位置需要的信息安排正文，逻辑清晰、关系简单时保持连续叙述。必要前提先解释，再展开依赖它的推理；流程按真实发生顺序和依赖组织，条件放在动作前、结果紧邻动作后。先给结论的总—分表达仍然适用，不等于把结果、前提、动作反复穿插，也不要求按作者调查或工具执行顺序写。

- 一次判断所需的规则摘要、适用条件、例子或未定问题尽量就近。正文写“待确认”时说明具体缺口及其影响，不能只写“见待定项”让读者到文末解码。集中问题清单可作跟踪索引，不能替代当前段落的必要解释。
- 不让简单主线在正文、表格、图、附录之间反复跳转。首次概览可简短，随后沿主线连续展开；技术细则、完整证据或真实分支可以另放，使用处保留理解所需摘要，说明引用用途，必要时明确回到哪一步。不复制全部细则来追求零跳转。
- 实施表按真实依赖排列，历史编号只作定位；不要先列一张看似顺序执行的表，再让读者按后文重新排序。任务编号保持稳定，调整行序或拆清不同交付阶段即可，不能为阅读方便改写实际历史或任务身份。
- 顺读检查时，记录“当前位置→被迫跳到哪里→为何必须跳→能否就近补充或重排”。遮住未读后文，检查本段是否已能理解、判断和继续；再检查跳读入口的局部说明。章节数量、目录齐全或链接有效都不能代替这项判断。

例如（虚构）：表格先列“调用服务”，后列“提供服务”，段末再补“须先完成后者”，会迫使读者重排。应依次写“提供服务→接入调用→联合验证”，原任务 ID 留作旁列。若服务返回规则尚未确定，在接入处说清缺口和对接入的影响，详细讨论再链接到原记录。

步骤的准备信息及动作—结果顺序参考 [Google 技术文档的流程写作指导](https://developers.google.com/style/procedures)；本文将其扩展为读者连续理解检查，不要求所有方案都写成操作手册。

## 3. 三个层面分别检查

### 内容与证据：能否作出正确判断

- 目标、对象、范围、版本和必要背景明确；术语在标题、图、表、正文中含义一致。内部标识可以帮助定位，不能代替对象说明。
- 关键判断给出读者能理解的证据摘要和适用条件。事实、推断、建议、示例、假设、待定事项分别表达；链接仅作查证与深读。
- 检查“因为/因此/说明/证明”：前提是否真的支持结论？个例是否被扩大为稳定性或普遍效果？比较是否同条件、同粒度？反例、成本和未验条件是否被省略？
- 技术含义保持：角色、权限、时间先后、否定、例外、单位、阈值、AND/OR 与成功条件不因简化改变。缺失原因和责任不能凭文风补写。
- 操作指南写清操作位置、输入来源、动作、预期结果与失败后怎么办。必须先满足的条件放在动作前；结果判据紧邻动作，不能藏在可选阅读或脚注。

### 阅读逻辑：只凭当下所知能否继续

沿主路径逐段读，先遮住后文与作者解释。每个角色仅使用其已知信息及已读正文，记录自己的复述与卡住位置，不给角色补作者记忆。

- 此处在回答哪个问题？读者知道为何需要这个概念、方案或操作吗？
- 前一句怎样支持后一句？换主题、主体、时间或抽象层级时是否有必要衔接？
- 读到每个动作，能说清谁做了什么、涉及什么人或事物吗？即使没有代词，也要检查读者是否只能猜。出现代词时，读者实际会把它理解成谁或什么？定义是否晚于使用，图中是否提前引入术语？
- 选择依据与选项、问题与回答、操作与结果是否相邻？是否为一次判断反复翻页记忆？
- 下一步需要的文件、状态或权限是否来自已说明的前置条件或前一步产物？中断后返回是否能定位当前状态？

按[共用规则](common-review.md#信息自闭环与角色知识边界)完成无外链复读。长文按完整文档及可独立进入的摘要/任务页分别检查；不用“自包含”要求每段复制全部前文。

### 阅读体验：能否省力地读、找和比较

只要读者是人，优先用图表达关系与足够的信息密度，通过分块、连线、标注和就近说明降低阅读难度；以清晰易读的手绘文字、白板风格降低阅读压力，不按内部/外部受众机械切换风格。按[画板表达指导](diagram-and-board.md)选择适合的表达，HTML/CSS、SVG、画板或 imagegen 均可，形式服从理解效果。关键点文字补足图中不宜承载的论证，大块文字分段、分点，避免长句堆砌。保留适用的可编辑源或生成提示词，并核对正文、图稿和实际呈现；简单内容不为配图增加阅读负担。

- 标题描述内容，层级表达关系；删装饰性副标题、无增量的开场白、空泛预告和重复总结。概念解释与必要背景不按“说明文字”一概删除。
- 一个段落推进一个主要判断，保留自然连接。中文遵循目标读者的语言习惯，避免生造词、翻译腔和机械短句；不要把长句拆成一串失去因果的碎片。
- 顺序动作使用编号，真正并列的信息用列表，多维比较用表格；连续论述用段落。避免整篇表格化、过深嵌套或每句一个标题。
- 图与表应减少理解成本。检查图中方向、名称、分组、图注与正文一致；图靠近引用位置，必要结论也能从文字获得。示意图不能冒充实际结果。
- 代码前交代目的与输入，代码后解释观察结果和限制；完整可复制指令放在使用处。区分真实 API 与自定义辅助函数，示例输出与实际运行证据。未知路径不捏造成存在的文件。
- 兼顾顺读和查阅：清晰目录、准确标题及必要的局部上下文帮助返回。渐进式展示可收纳详证、扩展例子与历史，但主结论、适用前提、操作后果和当前判据必须在阅读点可见。
- 在实际交付格式检查行宽、段距、字体、表格宽度、代码换行、图片清晰度、标题与内容分页。不要缩小字号来遮盖拥挤；标题、引导句和直接内容尽量保持相邻。脱离颜色后仍能理解信息。

### 按读者用途写中文应用文

**取材约定。** 维护本节及中文病句指导时，先读教材正文中的讲解、例题、练习或课文范例，再写规则。每项注明书名、版次或册次、章节或书内页码，并链接可核对的正文。课程介绍、目录、教案和题库只能提供检索线索。未找到正文依据的经验暂缓收录。教材观点用自己的话归纳，自拟示例单独标明。用户指定的标点偏好和用于核对符号用法的国标在下一节分别标识。

- **决定讲什么。** 交代事情经过时，沿发生顺序叙述。帮助读者弄懂某件事物时，挑出与目的有关的特征、关系或功能，再选择举例、分类或图示。教材分别讲解了叙述与说明的用途。见[《应用文写作实训教程》第2版，“项目综述”中关于表达方式的讲解，书内第11页前后](https://www.tup.tsinghua.edu.cn/upload/books/yz/069292-01.pdf)。
- **决定怎样说。** 同一件事写给谁、在什么场合使用，会改变用词的分寸。教材区分社交文书、公文和学术论文所需的语气，也提醒写作者检查近义词的范围、轻重和搭配。八年级的班会发言稿练习让学生结合说话人的身份，修改和场合不相称的评价。见[《应用文写作实训教程》第2版，书内第11至12页](https://www.tup.tsinghua.edu.cn/upload/books/yz/069292-01.pdf)、[八年级上册《表达要得体》，书内第151页](https://fliphtml5.com/cozhh/jviy/%E4%B9%89%E5%8A%A1%E6%95%99%E8%82%B2%E6%95%99%E7%A7%91%E4%B9%A6%C2%B7%E8%AF%AD%E6%96%87%E5%85%AB%E5%B9%B4%E7%BA%A7%E4%B8%8A%E5%86%8C/158/)。
- **从范文核对读者还缺什么。** 三年级的寻物启事交代失物的特征、遗落的时间地点、拾到后如何联系，并有署名和日期。用于类似文稿时，从拾到物品的读者角度复读，看他能否辨认物品、找到失主。其他体裁按各自目的选择信息。见[三年级下册《语文园地》寻物启事，书内第96页](https://fliphtml5.com/cozhh/mxtm/%E4%B9%89%E5%8A%A1%E6%95%99%E8%82%B2%E6%95%99%E7%A7%91%E4%B9%A6%C2%B7%E8%AF%AD%E6%96%87%E4%B8%89%E5%B9%B4%E7%BA%A7%E4%B8%8B%E5%86%8C/#p=101)。

### 中文标点、指代与省略

**先辨认并列的是什么，再选标点。** 同一层的并列词语或短语通常用顿号，如“清单列出负责人、截止日期、交付物”。有两层关系时，组内的词语用顿号，组间的分句用逗号，如“申请人核对姓名、地址，经办人核对金额、日期”。只有一层也不一定用顿号：“申请人提交材料，经办人核对金额”是两个分句。长段写完一个意思就用句号，不靠连续逗号串起不同议题。

**本项目在连续行文中少用分号，优先把它用于同一句领起的分项列举。** 有序编号或项目符号均可使用。各项并列、内部没有句号时，前几项末尾用分号，最后一项用句号。例如：

交接时，请核对以下两项：

1. 核对清单中的负责人、截止日期；
2. 确认接手人已收到最新图稿。

编号本身不决定标点。若各项独立成段，且已有一项包含完整句子并使用了句号，就不要在各项末尾再加分号。国家标准也允许用分号区分复句中较高层次的分句，不能把项目的少用偏好写成“正文禁止使用分号”。规范依据见 [GB/T 15834—2011《标点符号用法》](https://www.moe.gov.cn/ewebeditor/uploadfile/2015/01/13/20150113091548267.pdf) 的逗号、顿号、分号条目及附录 A、B。

**省略和指代以读者在当前位置能否准确理解为准。** 通读时先检查意思是否完整，再检查代词指向。按以下顺序判断：

1. **检查必要信息。** 读到动作或事件时，用完整的话复述谁做了什么、动作涉及什么对象，或发生了什么事。只检查理解本段所必需的信息。即使句子没有代词，也要检查省去的主语、宾语或名词。尤其注意只写数量和量词的地方：读者知道数量，不等于知道所说的事物。
2. **判断能否省略。** 读者凭本句和紧邻的上文就能明确补出所缺内容，且不影响理解，可以省略。必须靠猜测、回看远处文字、等待下文解释，或依赖作者才知道的背景，说明这里缺少必要信息。即使只有一种看似合理的猜测，也不能当作正文已经交代。
3. **判断指代是否清楚。** 先找代词在近处上文中指向的人或事物。所指唯一且自然，就保留代词。改换称呼本身不构成歧义。找不到所指，或存在会改变读者理解的多种合理解释，才记录问题。
4. **修订并复读。** 记录原句、读者无法确定的具体内容和病因。根据已确认的事实，在首次需要理解的位置补出必要成分，或写明代词所指。材料不足时写明待确认的问题，不替作者猜定。将改句放回原段，以同一读者身份顺读，核对人物、动作、对象及其关系，确认既能读懂，又没有增添事实或改变原意。

教材依据见下文八年级下册《句子结构要完整》第32页及高中选修《语言规范与创新》〈歧义多解〉第55至57页。上述步骤将教材的成分完整与消除歧义要求用于文档走查。

### 中小学病句检查与修正

先把句子放回原段读一遍，明确原来要表达的意思。小学阶段可从事实和漏写的信息入手。《国宝大熊猫》的习作练习要求学生写完自己读，补充缺失内容，用学过的修改符号改正不准确处，也可让同学再检查。句子读着别扭时，再用八年级教材的方法找出具体病因。下表是把教材方法用于日常文档的**自拟例句**。见[三年级下册，书内第94页](https://fliphtml5.com/cozhh/mxtm/%E4%B9%89%E5%8A%A1%E6%95%99%E8%82%B2%E6%95%99%E7%A7%91%E4%B9%A6%C2%B7%E8%AF%AD%E6%96%87%E4%B8%89%E5%B9%B4%E7%BA%A7%E4%B8%8B%E5%86%8C/#p=99)。

| 检查什么 | 怎样发现和修改 | 病句 → 改句 | 教材正文 |
| --- | --- | --- | --- |
| 成分残缺 | 暂去修饰语，读出谁做什么。如果动作缺少必要的主体或对象，补回缺项，或去掉遮住主语的词。 | “通过这次讨论，使两组达成一致。” → “通过这次讨论，两组达成一致。” | [八年级下册《句子结构要完整》，第32页](https://fliphtml5.com/cozhh/iibd/%E4%B9%89%E5%8A%A1%E6%95%99%E8%82%B2%E6%95%99%E7%A7%91%E4%B9%A6%C2%B7%E8%AF%AD%E6%96%87%E5%85%AB%E5%B9%B4%E7%BA%A7%E4%B8%8B%E5%86%8C/#p=39) |
| 语序不当 | 把并列动作逐个读出来，对照事情发生的先后。修饰语较多时，另查每个修饰语究竟限定哪个词。 | “请先公布结果，再核对并汇总选票。” → “请先核对选票，汇总后再公布结果。” | [八年级下册《语序要合理》，第15页](https://fliphtml5.com/cozhh/iibd/%E4%B9%89%E5%8A%A1%E6%95%99%E8%82%B2%E6%95%99%E7%A7%91%E4%B9%A6%C2%B7%E8%AF%AD%E6%96%87%E5%85%AB%E5%B9%B4%E7%BA%A7%E4%B8%8B%E5%86%8C/#p=22) |
| 句式杂糅 | 找出挤在一起的两种说法，根据句子要说明的对象选一种，读通整句。 | “这份手册的读者是为新员工编写的。” → “这份手册是为新员工编写的。”或“这份手册的读者是新员工。” | [八年级下册《句式不要杂糅》，第38页](https://fliphtml5.com/cozhh/iibd/%E4%B9%89%E5%8A%A1%E6%95%99%E8%82%B2%E6%95%99%E7%A7%91%E4%B9%A6%C2%B7%E8%AF%AD%E6%96%87%E5%85%AB%E5%B9%B4%E7%BA%A7%E4%B8%8B%E5%86%8C/#p=45) |
| 用词或搭配不当 | 看词的含义、褒贬和搭配是否符合原意。几个对象共用一个动词时，分别读一遍。 | “请提高校对质量和差错率。”若目标是减少错误，可改为“请提高校对质量，降低差错率。” | [八年级上册《表达要得体》，第151页的用词练习](https://fliphtml5.com/cozhh/jviy/%E4%B9%89%E5%8A%A1%E6%95%99%E8%82%B2%E6%95%99%E7%A7%91%E4%B9%A6%C2%B7%E8%AF%AD%E6%96%87%E5%85%AB%E5%B9%B4%E7%BA%A7%E4%B8%8A%E5%86%8C/158/)、[《应用文写作实训教程》第2版，“准确恰当”](https://www.tup.tsinghua.edu.cn/upload/books/yz/069292-01.pdf) |

下面三类病句尤其需要对照原意。诊断依据见各项所列教材正文，例句及复核问题均为本指导自拟。

- **成分赘余。** 圈出疑似重复的两个成分，试删其中一个，再问它原本提供了什么信息。“预计约需三天左右”中，“约”和“左右”都表示概数，可改为“预计约需三天”。复读时分别核对“约”和“预计”承载的意思，前者保留天数的近似范围，后者保留预测的语气。如果改成“工期为三天”，就把估计写成了确定期限。教材的练习要求在保留原意的条件下删去语义重复的词语。[七年级下册《语言简明》，书内第157至158页](https://fliphtml5.com/cozhh/jfkv/义务教育教科书·语文七年级下册/165/)
- **表意不明，尤其是指代不清。** 先按上节检查是否省去了理解所需的成分，再核对已有代词的所指。若存在多种合理读法，写明不同理解会改变哪个主体、对象或责任；按已确认的原意修订，放回原段核对。教材通过同一句中两个可能的动作主体，演示了分别补出主体的改法。[高中语文选修《语言规范与创新》〈歧义多解〉，书内第55至57页，例55至60](https://fhxxa.1088.com.cn/upload/downloadCenter/20200206/1580953783585.pdf)
- **不合逻辑。** 把句中判断分开复述，核对前后是否矛盾、否定有没有把意思说反、所列条件能否推出结果。“只要提交申请，就能获批”把提交写成了获批的充分条件。若原规则只规定获批前必须申请，可改为“只有提交申请，才可能获批”。复核时分别代入未提交和已提交两种情形。前者不能获批，后者仍可能未获批。两种情形都与原规则相符，才保留改句。原规则未交代审批条件时，先查明规则，再改关联词。[高中语文选修《语言规范与创新》〈不合逻辑〉，书内第53至55页，尤其是例38至39](https://fhxxa.1088.com.cn/upload/downloadCenter/20200206/1580953783585.pdf)

改完连同前后句复读，核对原意是否保留。若有两种改法且意思不同，先回到上文判断作者想表达哪一种。根据八年级上册《表达要得体》的练习，局部替换仍讲不清时，可以保留原意重写整句。[八年级上册，书内第151页](https://fliphtml5.com/cozhh/jviy/%E4%B9%89%E5%8A%A1%E6%95%99%E8%82%B2%E6%95%99%E7%A7%91%E4%B9%A6%C2%B7%E8%AF%AD%E6%96%87%E5%85%AB%E5%B9%B4%E7%BA%A7%E4%B8%8A%E5%86%8C/158/)

## 4. 融入 STE，同时保持原意

用[STE 规则索引](ste100-writing.md)区分自然中文借鉴、普通英语清晰写作与正式 STE 审查。默认将它用于降低歧义，而不是改变项目术语、改写 API 名称或替代技术事实核验。

遵循[面向人的用词规则](human-facing-expression.md)：先判断通识性词语、行业共识名称或完整描述是否足以表达，通常不新造词或简称。术语表服务于非常必要的例外，不是造词许可。不得把只有通读作者会话才理解的缩写、编号代称带入正文；例外保留的会话专用词须在当前材料提供全称、含义，通常不超过 10 个，极限 15 个，并与当前会话术语表一致。正式英语 STE 另核对词典义项/词性、允许形式与领域术语依据；现有行业词典、准确的 API 定义不属于自行造词。相同对象不要为文采换名；不同概念也不能为了统一而合并。Agent 间通信的豁免不延伸到给人阅读的正文、图表或说明。

改写后逐项比较：谁做什么、对谁/什么做、何时/什么条件、应得结果、失败路径、限制与责任。凡是未能保留的语义，重写或明确待核实；不能以“更简洁”作为丢失内容的理由。

## 5. 从记录到修订闭环

在共用清单中使用[文档记录视图](../assets/document-review.md)，补充具体正文位置和阅读卡点，避免只写“逻辑不顺”“已润色”。编号、状态及通用读回流程统一遵循[共用规则](common-review.md)。

修改顺序通常是事实与语义→结构/概念顺序→段落衔接→句子/术语→呈现。对共享根因统一修订，但复查受影响的角色和章节。保留必要原文片段或差异，防止只看到 after 文本就判通过。

保存后重开实际文件或页面，沿原角色与相同知识边界复读；查阅源文件不能代替已发布正文读回。多格式材料核对同源版本与受影响内容。PDF/Word/演示文件还需渲染判读，Notebook 检查说明、代码与输出顺序。文档含可执行步骤时，仅按授权与影响执行必要复现；纯说明稿不强加运行或压力测试。

结论分别写内容与证据、阅读逻辑、语言、呈现、适用的操作复现。未渲染、未运行或资料不足的项目标为待验，并说明缺口。主体推理有缺项时先修正文；不能把“等待用户阅读”当作已授权修订的完成条件。确需真实读者证据时提出有针对性的阅读任务和观察问题，不把审查者模拟当作真人理解率或学习效果。

## 6. 例子：避免把作者上下文留给读者猜

**原稿（虚构）**：“按之前的方案生成，再看结果，没问题就提交。注意：需管理员确认且不能含客户数据。详情见旧记录。”

**已知事实（虚构）**：目标是为演示生成测试报告；在测试环境使用合成数据；操作者先检查报告的数据来源和失败项；管理员确认后才能提交。未提供具体命令和提交入口。

**修订**：“本流程用于生成并提交演示用测试报告。在测试环境中使用合成数据，报告不得包含客户数据。生成报告后，检查数据来源和失败项。管理员确认报告后，再提交报告。”

独立执行者现在能复述目标、范围、检查和先后条件；实际生成命令、检查方法与提交入口仍缺失，应继续补齐，不能标记“可独立执行”。评审者需要看到确认内容与效力，而不只是“没问题”。修订示例说明结构与语义检查，不是 STE 英文合格样例，也不是已验证的操作流程。
