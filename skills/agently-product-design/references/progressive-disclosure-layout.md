# 渐进式展示与布局决策

目标是让用户在当前任务中容易判断、容易行动，并能找到必要细节。以下决策表与场景是本 Skill 的应用指南，不是书籍原文，也不构成对所有产品的固定布局要求。

## 1. 区分三种安排

NN/g 的渐进式展示建议将次要选项按需展开，强调内容分层和入口含义；它与按时间顺序推进的分步展示有区别。互相依赖、需要反复比较的决定不宜拆散。[Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)

| 安排 | 适用条件 | 需要验证什么 |
| --- | --- | --- |
| 按需展开 | 用户当前可以完成任务，但部分人需要补充细节或高级选项 | 收起仍足以判断；入口能预告内容；展开后可以回到任务 |
| 按上下文出现 | 动作与选中对象、编辑模式或当前任务相关 | 触发条件可理解；触摸/键盘也能发现；操作目标不因出现而跳走 |
| 分步推进 | 任务确有先后阶段，后一阶段暂时不可执行或不必处理 | 已选信息可回看和修改；更改前一步时解释后续影响；不要拆开比较依据 |

收纳与权限控制、延迟加载是不同问题。分步流程也不等于“字段太多就切几屏”；应检查每一步的决策关系与返回成本。

## 2. 先做信息清单，再选控件

逐块说明：谁在何时使用、服务哪个判断、频率证据、出错后果、需同时阅读的内容、当前是否已生效。缺少证据时标假设。

| 内容/动作条件 | 默认考虑 | 防止的失败 |
| --- | --- | --- |
| 当前判断所需的对象、条件、关键结果、主要动作 | 在任务工作区直接可见，并合理归组 | 用户在信息不足时作决定 |
| 不常用，但当前存在错误、阻塞、未保存内容或重要影响 | 关键状态/后果在相关位置可见，细节按需查看 | 用“低频”把当前问题藏起来 |
| 可独立查询的历史、技术细节、低频选项 | 具名入口与必要摘要，详情可展开 | 用户不知道有内容或猜“更多”里装什么 |
| 与主任务持续对照的依据 | 支持并排/邻近查看或稳定切换并保留上下文 | 在互斥标签页间依赖记忆比较 |
| 多处展示相同信息 | 保留有定位/确认用途的必要摘要，合并其余重复 | 为去重删除必要上下文，或不同副本产生冲突 |

把最终决定填入工作记录的“展示层级决策”，并关联项目规范中的模式 ID。不要仅以页面是否清爽决定收纳。

## 3. 依据任务选择容器

下面是候选比较表，实际选型还需遵循项目和平台约定。

| 候选 | 通常适用 | 代价与退出条件 |
| --- | --- | --- |
| 原位展开/详情块 | 补充内容直接解释邻近字段或结果 | 展开会推移下方内容；长篇/多组同时阅读时考虑直接排版。GOV.UK 也明确不将多数用户需要的内容放入详情控件。[使用指导](https://design-system.service.gov.uk/components/details/) |
| 并排辅助区/非模态侧面板 | 需保留主对象，查看依据或处理短任务 | 必须保留足够核心工作区；窄屏可换呈现方式，但要保持对象、数据和返回路径 |
| 标签页 | 同一对象的相对独立视图 | 不适合必须同时对照的内容；切换要保留适用的输入/位置，未处理事项应可发现 |
| 专门任务页 | 长内容、复杂编辑、独立地址或可恢复的任务 | 需要对象上下文、合理返回与进度承接；不要让用户重找入口 |
| 模态对话框 | 短而聚焦、需要临时独占注意力的决策或输入 | 阻止背景交互；不能一边要求读背景依据一边遮住它。定义取消、关闭和焦点恢复 |
| 更多菜单/上下文工具 | 有明确所属对象的次要命令或选择后操作 | 高优先动作不能难以发现；已激活选项/任务不能因菜单关闭而失去可见反馈 |

“抽屉”只描述外观时不足以形成规格：必须说明它是模态还是非模态、背景能否操作、焦点如何移动、内容是否被覆盖，以及如何关闭。不要仅因某种组件流行就采用。

## 4. 布局要表达任务关系

《Don’t Make Me Think》的公开摘录强调：视觉显著程度表达重要性，归组表达关联，嵌套表达归属；清楚的选择比机械减少点击更有价值。依据为第 3 版的[视觉层级摘录](https://www.peachpit.com/articles/article.aspx?p=2209310)和[作者授权第 4 章样章](https://sensible.com/downloads/DMMT-Revisited-sample-chapter.pdf)，未将整本书视为已读。

执行布局设计时：

1. 写出当前任务的一句话目标；标出用户需要先知道的对象、状态和结果，再安排相应操作。
2. 将一次判断所需的依据、输入、动作和反馈放在可连续扫读的位置。标题覆盖正确的内容组，组内关联比组间更清楚；检查卡片套卡片是否掩盖真实关系。
3. 按用途分配阅读区、编辑区和辅助区，使用真实长度及数量。留白服务分组和阅读；数据表、正文阅读与画布有不同密度需求。
4. 在同视口、同数据、同状态比较核心有效区域和可见关键内容，同时记录遮挡、换行、滚动与切换代价。主区域变大但比较更难，不能算优化成功。
5. 为收纳/展开、错误、加载和窄屏分别检查；说明主要滚动容器、吸顶/固定区域和焦点可见性。不要把所有区域都做成相互竞争的小滚动窗。

### 界面文案：默认不添加说明区

页面标题下不默认配副标题、功能概述、欢迎语或介绍段；卡片、面板和工具栏也不因为“还有空位”而添加一句解释。用户应通过对象名称、分组、控件与状态直接理解普通任务。长篇说明若在解释普通按钮怎么用，先检查命名与结构是否有问题。

此删减规则不适用于理解任务、评审或需求主体所必需的背景、前提、依据与逻辑衔接。这些是主体内容，必须在当页齐备；外链或隐藏帮助不能代替。按[无外链读者走查](walkthrough-guide.md#信息自闭环不跳页的读者走查)确认删减后仍可独立理解，再判定哪些文字冗余。

逐句问：删掉后，用户会缺少哪个当前必需的判断？

| 文案情形 | 处理方式 |
| --- | --- |
| 重复标题、按钮或当前界面已经表达的内容 | 直接删除，尤其是“在这里你可以…”“点击下方按钮…”一类重复提示 |
| 泛泛的产品介绍、宣传语、礼貌性欢迎、形容界面价值 | 从用户工作区删除；不把主任务下推给介绍段让位 |
| 解释普通操作的长段说明 | 优先改清楚对象、名称、分组与控件，再判断是否还有必须说明的部分 |
| 当前决定必需的范围、单位、格式、条件、操作后果或恢复办法 | 用最短但完整的表述放在相关字段、状态或动作附近；保留有信息价值的标题与标签 |
| 仅少数任务需要的背景知识、复杂概念或详细帮助 | 先确认确实有用，再提供可发现的按需帮助；不要把无效文案搬进折叠区或 tooltip |
| 设计理由、框架介绍、实现细节、走查结论 | 写入设计/开发文档；只有确实影响用户决策的部分才转成用户语言 |

例如，“任务”标题下的“在这里查看、创建和管理任务，让协作更高效”可直接删除，保留任务内容及“新建任务”动作。空列表里的“暂无任务”说明实际状态，可与创建入口保留。删除操作会影响哪些对象、失败后怎样恢复等信息有明确用途，应在发生时简短呈现。

共用页面头部、卡片和空态组件不得要求填写副标题或说明字段；可选说明为空时不渲染占位区和对应空白。不要生成通用兜底介绍，也不要把缺少说明判为页面不完整。

验收同时检查删减后的直接可理解性与必要信息是否完整：看标题、内容、控件和状态能否定位对象并判断下一步；关键条件与错误恢复是否仍可见；是否腾出了真正可用的任务空间。不要用隐藏字段标签、只留难懂图标或截断必要正文换取字数减少。

这项应用规则响应用户明确要求，并与 NN/g 关于减少无关信息竞争注意力的原则相符。[Aesthetic and Minimalist Design](https://www.nngroup.com/articles/aesthetic-minimalist-design/)。《Don’t Make Me Think》第 3 版目录也列有第 5 章“Omit needless words”；本轮仅核对该目录，不据此声称已阅读全文。[出版方目录](https://www.peachpit.com/store/dont-make-me-think-revisited-a-common-sense-approach-9780321965516)

## 5. 定义展开与返回的完整行为

- 收起：入口文字说明内容，按需保留已选值、筛选生效状态、未处理数量或错误提示；不要每块都堆一排徽标。
- 展开：触发范围清楚，用户知道改变了哪里，核心任务不无故重排或丢失位置。
- 操作：保存中、失败、完成等含义准确；收起不等于取消任务，关闭不自动等于保存。
- 返回：保留合理的输入、选中对象和滚动；焦点回到触发处或明确的下一步。持久化个人展开偏好时限定用户/对象范围，不能复用上个用户的业务数据。

Web 实现按控件语义选择原生能力或核对相应模式。展开控件需提供可操作的按钮语义与展开状态；模态框需处理入场、内部焦点移动和退出。具体行为见 [APG Disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) 与 [APG Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。组件符合示例不等于整页可访问性已验收。

## 6. 示例：同一工作台，因任务而采用不同展示层级

这是设计推演，不是任何现有项目的实测结论。

- 编辑者需对照审阅意见修改正文：将正文和当前意见保留在同一工作上下文；历史处理记录可按需查看。如果并排后正文太窄，验证可调宽度或稳定切换方案，而不是强制把意见全部藏入菜单。
- 观察者看进展：显示对象、进度、待处理结论与必要条件，展开后查看来源；复用同一状态含义与详情组件，避免另造一套文案。
- 导出只有格式细节较少使用：主要导出入口应可发现，高级选项可展开；若所选范围可能漏掉关键内容，范围与生效过滤条件应在提交前可见。

用整页图比较空间，用组件图表达收起、展开及错误/待办状态。图的数量由待解决问题决定；按[Imagegen 闭环](imagegen-design.md)落实为组件规格与真实操作验收。

## 7. 验收与反证

选首次使用与熟练使用等真正有差异的情境。观察用户能否找到入口、预测动作结果、找到关键条件、处理一次错误并返回原任务；不提示“点右边那个”。记录犹豫、误选、往返、反复展开与内容丢失，以及业务结果。缺少真实用户时可做审查者推演，但保留待研究状态。

为每项写可观察标准，例如“收起高级筛选后仍能识别已生效的范围；回到列表时筛选与选中对象保持”。数字目标来自项目基线或明确约定，不套用三次点击、固定层数、固定面积占比等通用门槛。

如果展开次数明显增多、任务需要记住不可同时看到的信息、熟练用户效率下降或关键条件更难发现，重新调整展示层级。保持“容易理解与完成任务”的目的，不把某个控件本身当目标。
