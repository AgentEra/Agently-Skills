# 文档撰写与读者走查

让目标读者仅凭交付正文理解问题、作出判断或继续行动。按角色已知信息设计阅读顺序，再将具体卡点、修订与复验记录下来。能复述结论、能执行步骤、成品可读分别检查，不以文字流畅代替事实和逻辑正确。

先执行[统一入口](../SKILL.md)的共同方法及[共用审读与修订规则](../references/common-review.md)，已读过不重复加载。此模块负责表达与阅读验证；涉及方案实质取舍时同时按[方案设计模块](solution-design.md)检查论证基础。表达完整不证明设计机制正确。

## 1. 确定任务与读者

先读项目写作规范、当前稿件、有效事实与已有 checklist，确认修改范围、语言、读者、成品格式和唯一源稿。可从资料查明的信息直接查；关键未知信息保留待补，不为写顺而编造事实、命令、路径或责任。

读取[文档撰写与读者走查](../references/document-writing.md)，按材料选择首次阅读者、决定者、接手执行者或返回查阅者。明确各角色已知与未知、可见材料、当前问题及读完应能完成的事。作者聊天、旧方案、授课口头补充不是读者默认背景；同一人承担不同角色时也要区分责任。角色模拟不要求启动多个 Agent。

多读者的职责交接、操作分支或权限会改变阅读结果时，按需读[角色与行为覆盖](role-behavior-coverage.md)，只使用相关阅读/行动路径，不要求普通文稿遍历 UI 状态。

新稿先确定信息依赖与连续阅读/行动路径；旧稿先通读标记，再改结构、段落与句子，最后全文复读。小段修改只检查受影响内容，不为了填表扩展工作。

## 2. 将共同方法用于文稿

信息自闭环与同角色保存后复读按共用规则执行。长文以完整文档及可独立进入的摘要/任务页为单位，不要求每段重复背景。作者备忘、教师安排与正文分开，保留读者必需的概念解释与条件。方案材料检查“观察及证据范围→问题与原因→机制为何有效→效果、代价与前提→验证”是否在主体表达完整；发现设计依据缺口时记录并回到方案判断，不能靠润色补造。

## 3. 分别检查内容、逻辑和体验

内容核对事实、证据、推断与假设，保留对象、条件、否定、数值、责任与技术含义。逻辑检查概念首次出现、前提与结论、指代、段落承接、选择依据及前后步骤输入输出。阅读体验检查标题、归组、冗余、自然语言、图表与代码位置，以及实际成品的行宽、分页和可读性。

品牌提案、演示式方案、图文说明或迁移已有展示效果时，读取[视觉叙事与载体选择](../references/visual-storytelling.md)。先识别参考中的视觉关系，再选择原生文档、可编辑画布、受支持的嵌入或合适的插件；不能把富表达内容静默压成连续段落，也不能只恢复加粗就宣称还原了展示效果。具体风格是按任务选用的表达方式，不是所有文档的固定模板。

需要 STE 规则时读取[ASD-STE100 应用指导](../references/ste100-writing.md)。中文借鉴术语一致、指代明确、条件前置和指令清楚等原则，不把英语 20/25 词套为中文字数；正式英语 STE 审查须核对指定版本完整适用规则、词典及领域术语，不以短句或自动计数宣称全文符合。简化后逐项比较原意，不为文风改变技术要求。

## 4. 用画板表达必要关系

面向人的表达先按统一入口组织图文，读[画板表达指导](../references/diagram-and-board.md)。优先让一张综合图或同一连续阅读面表达完整核心信息，以分块、关系、就近标注和说明保持有效信息密度；一般图示可用原生画板、HTML+CSS、SVG 等；技术架构梳理默认按[架构与流程图表达](../references/diagram-and-board.md#架构与流程图的默认表达)交付 SVG 逻辑分层图，流程图先区分主次链路与业务职能块。需要展开的文字按主题分段、按并列或步骤分点，不把长句塞进图形，也不重复图中已清楚的信息。

手绘文字与白板风格是面向人的减压表达偏好，不限内部或技术材料；明确品牌、当前任务或正式记法另作约束。可用 imagegen 辅助探索形式，但需逐项核对内容准确性。保留适用的可编辑源，核对图文一致、实际尺寸可读、导入/编辑/重开及资源完整性。图已生成、文件可解析、远端保存成功不能互相替代；无画板环境时如实保留未验范围。

## 5. 修订、读回与交付

在共用清单中使用[文档记录视图](../assets/document-review.md)，补充术语、概念依赖、正文位置及各格式呈现结论；不另建互相冲突的状态表。

保存后重新打开实际文件或页面，按原角色及相同知识边界复读。内容、逻辑、语言、呈现、适用的操作复现分别下结论。多格式交付核对源稿、Notebook、PDF、图稿与分发包版本；可用时结合对应文档制作技能完成渲染判读。纯文本审读不等于视觉通过；静态模拟不等于真人理解率或学习效果。

需要操作复现时按授权与改动范围验证，缺少条件则写具体待验项。写作授权不自动包含对外发布或改变技术约束。交付说明改了什么、实际证据、未完成项与下一动作，不把旧版结果当作本轮验证。
